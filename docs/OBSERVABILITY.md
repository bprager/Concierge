# Observability

## 1. Observability goals

Concierge must be inspectable.

For each interaction, we should be able to answer:

1. What did the user ask?
2. Who was the user profile?
3. What did Concierge infer?
4. Which stance was selected?
5. Which context was requested?
6. Which governance decision was made?
7. Which agent was routed to?
8. What response was produced?
9. What latency and errors occurred?
10. What should improve?
11. Which conversation capabilities are common, working, missing, or blocked by architecture?

## 2. Signals

The system emits:

- Traces
- Metrics
- Structured logs
- Evaluator reports
- Privacy audit records
- Evolution proposals
- Conversation capability signals

OpenTelemetry is the preferred standard for traces, metrics, and logs because it is vendor-neutral and supports multiple languages and destinations.

Capability review packet export is a local rendered artifact, not a Napoleon audit stream. It may contain sanitized answer rows, review focus, evaluator-case candidate, evolution-proposal draft, and explicit local-only boundary fields, but must not contain endpoint hosts, bearer tokens, raw prompts, request bodies, response bodies, raw audio, or raw video. Exporting it does not send it, approve it, apply it, write memory, dispatch agents, or contact Napoleon. Governed packet submission emits metadata-only send started/completed/failed events and still cannot apply changes locally. Returned packet review metadata and exported packet state are cleared when the local capability ledger is cleared, Napoleon endpoint, bridge token, or descriptor context changes, the active user profile changes, or Rehearsal Mode is enabled so stale decision or audit evidence cannot outlive the local evidence, connection, credential, descriptor, profile, or live-mode context that produced the packet.

Local review history is a rendered inspection surface, not a Napoleon audit stream. It aggregates already-sanitized governed review results and proposal lifecycle metadata so the user can inspect what was reviewed, what proposal status is locally known, what decision/audit/trace references were returned, and which side effects stayed blocked. Text Concierge can also answer local review-history and proposal-status questions from this metadata, such as which reviews are waiting, what recently returned, or what the status of an evolution proposal is, without contacting Napoleon. Its `local_review_history_exported` and `local_review_history_answered` telemetry are metadata-only and classified as local observability. Export and answer telemetry exclude original conversation content, endpoint hosts, credentials, request bodies, response bodies, audio, video, and returned decision/audit/trace IDs, and they do not approve, apply, write memory, dispatch agents, send externally, update registries, activate agents, or apply evolution.

Rehearsal Mode evaluator-case candidates are rendered local draft metadata, not a Napoleon audit stream. They may show a sanitized intent summary, expected route, expected governance outcome, profile mode, allowed effects, blocked effects, trace ID, and evidence links so a human can seed evaluator coverage, but they do not approve, dispatch, write memory, send externally, or contact Napoleon.

## 3. Trace model

Every user turn has:

- trace_id
- conversation_id
- turn_id
- user_profile
- channel
- intent
- stance
- governance decision
- Napoleon request ID
- response ID

New-agent proposal review telemetry is local metadata only. Draft and send events use `new_agent_proposal_review_drafted`, `new_agent_proposal_review_send_started`, `new_agent_proposal_review_send_completed`, and `new_agent_proposal_review_send_failed` with trace/request/proposal IDs, proposed agent ID, named review target metadata, fail-closed reason, governance references when returned, and blocked effects. Local lifecycle tracking uses `new_agent_proposal_lifecycle_recorded` and `new_agent_proposal_lifecycle_exported` for drafted, sent-for-review, review-returned, and fail-closed states; stored lifecycle records retain only sanitized proposal metadata, decision/audit/trace references, profile scope, next action, and explicit false side-effect flags. These events are also classified as Conversation Capability Intelligence signals. They must not include raw proposal text, endpoint hosts, bearer tokens, request bodies, response bodies, registry writes, agent activation, approval capture, memory writes, agent dispatch, external sends, or local application.

Capability discovery telemetry, sanitized readiness proof exports, and the advisory capabilities panel distinguish Concierge local side-effect fields from response-side side-effect claim fields, so an unsafe Napoleon response can explain why discovery was blocked without retaining raw response content.

Capability-answer evidence drilldowns are local rendered metadata, not a new Napoleon audit stream. Their JSON export uses sanitized answer rows, score metadata, profile scope, and allowlisted evidence references only, and it must exclude raw prompts, endpoints, credentials, request bodies, response bodies, raw audio, and raw video. Exporting a drilldown does not contact Napoleon, capture approval, write memory, dispatch agents, send externally, or apply a recommendation.

Child-protected local Napoleon required-action answers are stricter than adult/operator answers. Governed memory proposal review responses that claim memory writes, approval capture, external sends, agent dispatch, or local application are reported as `contract_mismatch` failures through `memory_proposal_send_failed`.

Live text responses that claim memory writes, approval capture, external sends, agent dispatch, or local application are reported as `contract_mismatch` failures through `bridge_request_failed` and remain visible through the bridge-blocked transcript message. The local harness can emit matching forbidden-claim response shapes for text, Chief of Staff steering, memory proposal review, and explicit new-agent proposal review paths so local checks can keep those failure signals exercised.

New-agent proposal review handoffs use the explicit Napoleon review target `/chief-of-staff/reviews/new-agent-proposals` with the `new_agent_proposal_review_handoff` request kind. Retained local evidence records the named target path and operation only; it does not retain endpoint hosts, tokens, raw proposals, registry writes, approval capture, agent dispatch, external sends, or local application.

Chief of Staff request handoffs use the explicit Napoleon request target `/chief-of-staff/requests` with the `chief_of_staff_request_handoff` request kind. Retained local evidence records the named target path and operation only; it does not retain endpoint hosts, tokens, raw request bodies, task-routing side effects, registry writes, trace appends, approval capture, memory writes, agent dispatch, external sends, or local application. The governed route panel presents the target as request-handoff-only and shows task routing, registry update, trace append, approval capture, memory write, agent dispatch, external send, and local application as blocked Concierge effects.

Governance evaluation handoffs use the explicit Napoleon evaluation target `/governance/evaluate` with the `governance_evaluation_handoff` request kind. Retained local evidence records the named target path and operation only; it does not retain endpoint hosts, tokens, raw request bodies, approval capture, task routing, memory writes, agent dispatch, external sends, trace appends, registry writes, governance override, or local application. The governed route panel presents the target as governance-evaluation-only and shows governance override, approval capture, memory write, agent dispatch, external send, registry update, trace append, routing, and local application as blocked Concierge effects.

Local contract packet exports for these targets emit `chief_of_staff_request_packet_exported` and `governance_evaluation_packet_exported` telemetry. Governed submissions emit started, completed, and failed events for `chief_of_staff_request_packet` and `governance_evaluation_packet`. Those events keep only trace/conversation/profile metadata, request kind, target path, readiness or failure status, returned decision/audit IDs when present, and explicit false side-effect flags. They must not include endpoint hosts, bearer tokens, raw prompts, raw request bodies, raw bridge responses, approval material, memory contents, or agent contribution text. The exported packets and returned packet review results are local artifacts only and are cleared when the draft input, endpoint, bearer token, descriptor state, Rehearsal Mode, or active profile changes.

Evolution proposal submission handoffs use the explicit Napoleon target `/evolution/proposals` with the `evolution_proposal_submission_handoff` request kind. Draft, send-started, send-completed, and send-failed events are tracked as local Capability Intelligence signals with proposal ID, profile mode, safe named target metadata, governance references when returned, and blocked-effect counts, but not raw proposal text. Retained local evidence records the named target path and operation only; it does not retain endpoint hosts, tokens, raw proposal bodies, approval capture, memory writes, registry updates, trace appends, task routing, agent dispatch, external sends, or local application. Returned `deny` or `no_go` outcomes are classified as correct governance blocks, while real transport or contract failures remain bridge follow-up candidates. The governed route panel presents the target as proposal-submission-only and shows evolution application, registry update, approval capture, trace append, routing, local application, memory write, agent dispatch, and external send as blocked Concierge effects.

Observability trace handoffs use the explicit Napoleon target `/observability/traces` with the `observability_trace_handoff` request kind. The handoff packet is sanitized local evidence for Napoleon review only and fails closed if the descriptor does not advertise `observability_trace` or if the response claims trace append, audit authority, approval capture, memory writes, task routing, agent dispatch, external sends, or local application. Retained local evidence records the named target path and operation only; it does not retain endpoint hosts, tokens, raw trace bodies, approval capture, memory writes, trace append authority, task routing, agent dispatch, external sends, or local application. The governed route panel presents the target as trace-evidence-only and shows trace append, audit authority, approval capture, memory write, task routing, agent dispatch, external send, and local application as blocked Concierge effects.

When descriptor discovery has not completed or the descriptor discovery cache is stale, live text turns, memory proposal handoff, Chief of Staff steering handoff, and Chief of Staff taxonomy review handoff fail closed before request fetch and report descriptor mismatch failures with the relevant blocked-effect list. When Rehearsal Mode is active, memory proposal review, Chief of Staff steering, and taxonomy review submit helpers fail closed before request fetch and emit their governed handoff failure events with blocked effects.

Descriptor discovery failures preserve `auth_failure`, `bridge_timeout`, and `http_failure` as local connection states and emit `descriptor_discovery_failed` rather than `descriptor_discovery_completed`. If a user attempts a governed text turn, memory proposal handoff, Chief of Staff steering handoff, or taxonomy review handoff after one of those failures, the preflight failure event carries the same reason before any request fetch is attempted.

The persistent Napoleon delegation panel mirrors these descriptor discovery failure states before any selected-agent provenance is returned. Authentication failures, descriptor timeouts, invalid descriptors, stale descriptors, and descriptor HTTP failures show specific next-step guidance, visible blocked effects, and explicit absence of selected-agent or Napoleon recommendation attribution.

Local answers to Napoleon descriptor validity questions emit `napoleon_descriptor_validity_answered`. The event is metadata-only: it may record local-answer-only status, descriptor-valid-for-live-send boolean, endpoint configured boolean, descriptor/checksum/signature/freshness enum states, text-turn route advertised boolean, fail-closed reason, Rehearsal Mode state, next-action enum, and explicit false approval, memory-write, agent-dispatch, external-send, and local-application flags. It must not include raw question text, endpoint values, bearer tokens, descriptor bodies, prompts, request bodies, response bodies, trace-proof content, audit IDs, or returned agent/capability text. The rendered answer is local readiness guidance only and does not contact Napoleon or become Napoleon approval.

Explicit descriptor `supportedHandoffs` / `supported_handoffs` lists are treated as contract claims. When no explicit handoff list is returned, descriptor discovery may derive allowlisted handoff evidence from Napoleon's documented `required_for` values and plural review endpoint keys such as `evaluation_reviews`, `governance_reviews`, `governance_evaluations`, `chief_of_staff_requests`, `evolution_proposal_reviews`, `evolution_proposal_submissions`, `new_agent_proposal_reviews`, and `observability_traces`. Live-runtime validation uses the same evaluator-review advertisement evidence before deriving `/chief-of-staff/reviews/evaluation`, so `required_for: evaluation_review` does not get misreported as an unadvertised evaluator handoff. The allowlisted governed handoff names include generated Napoleon review, request, governance-evaluation, evolution-submission, new-agent-review, evaluator-review, observability, memory, steering, taxonomy, and text-turn names, so those routes can be advertised by the descriptor and carried into sanitized readiness proof as connection evidence only. Unknown governed handoff names in explicit handoff lists make descriptor discovery fail closed as an invalid descriptor instead of being dropped from telemetry or readiness proof state.

## 6. Logs

Logs must be structured JSON.

Avoid raw user content by default.

Example:

```json
{
  "ts": "2026-06-07T12:00:00Z",
  "level": "info",
  "event": "stance_selected",
  "trace_id": "trace_123",
  "turn_id": "turn_456",
  "user_profile": "adult_owner",
  "stance": "direct_strategic",
  "confidence": 0.82,
  "reason_code": "architecture_review"
}
```

Capability intelligence logs and persisted snapshots must avoid raw user content by default. Store timestamps, sanitized machine labels, counts, trend deltas, score components, confidence, privacy class, architecture area, suggested next step, taxonomy edits, retention settings, scoring caveats, and allowlisted local trace/event/audit references rather than transcripts. Sentence-like labels, email addresses, URLs, token-shaped values, and non-local evidence references are redacted before storage or export. Local export is JSON metadata only and does not grant permission to share externally.

## 7. Redaction policy

- Remove raw audio
- Remove raw video
- Redact email addresses where possible
- Redact child names unless explicit debug mode is enabled
- Replace message content with hashes or summaries when possible
- Preserve enough metadata for debugging

## 8. Local buffer

The local buffer stores telemetry when the collector is unavailable.

Initial local implementation: Text Concierge stores emitted telemetry payloads in a browser-local buffer at `concierge_telemetry_buffer_v1`. The buffer defaults to the latest 200 events, can be reduced to latest 100, 50, or 25 events from settings, redacts sensitive attribute keys such as raw prompts, raw text, response text, endpoints, bearer tokens, request bodies, response bodies, raw audio, and raw video, and does not send externally. Ordinary events are not buffered when local telemetry is disabled, but privacy audit events for camera, microphone, and privacy settings remain buffered so consent-relevant changes stay locally auditable. The Text Concierge settings surface shows the buffered event count and last event, can export the redacted local JSON metadata, can clear the persisted buffer, prunes existing buffered metadata when the retention limit is reduced, and clears rendered buffer and trace exports when retention changes. The buffer and its export are local metadata only; they are not Napoleon approval, not Napoleon audit records, not memory writes, not agent dispatch, and not permission to send externally.

Requirements:

- Bounded size: initial implementation defaults to the latest 200 events and lets the user reduce retention to latest 100, 50, or 25 events.
- Redaction: initial implementation redacts common raw content, endpoint, body, and token fields before storage.
- User-visible retention settings: initial implementation stores the selected latest-event limit locally and immediately prunes existing buffered metadata when reduced.
- Stale export prevention: initial implementation clears rendered buffer and interaction trace exports when retention changes.
- Manual delete option: initial implementation clears the browser-local buffer from the settings surface.
- Export option for debugging: initial implementation exports redacted browser-local JSON metadata from the settings surface.
- Encryption at rest when feasible: future work.
